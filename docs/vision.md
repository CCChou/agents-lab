# 家庭 Agent 與研究 Agent：設計討論筆記

> 這份筆記整理自先前的討論，作為開發的背景脈絡。
> 這是可能的長期走向，不是已確定的設計。實際順序與決策以 `docs/roadmap.md` 為準。

## 1. 家庭 agent 的使用情境

### 家務與採買
- 冰箱與庫存管理：記錄食材與保存期限，快過期時提醒，並依現有食材推薦食譜
- 一週菜單與購物清單：依口味、過敏、預算排菜單，自動產生清單，可串接外送或電商平台下單
- 日用品補貨：依使用週期提醒補貨，比價或等特價時買
- 家務分工：輪值表與提醒，可配合垃圾車時間

### 財務與帳單
- 帳單管家：水電、瓦斯、電信、保險、房貸的繳費期限提醒，用量異常時通知
- 家庭記帳：掃描發票或收據自動分類，產出月報
- 統一發票自動對獎
- 訂閱盤點：找出重複或沒在用的訂閱
- 稅務與補助：整理報稅扣除額，提醒可申請的補助

### 孩子相關
- 學校行事曆整合：把聯絡簿、學校群組通知整理成行事曆
- 作業陪伴：用引導方式解說，不直接給答案
- 才藝與補習接送排程：偵測行程衝突，協調由誰接送
- 成長紀錄：疫苗、健檢、身高體重追蹤，照片整理

### 健康照護
- 用藥提醒、慢性病連續處方箋到期提醒
- 看診預約，整理症狀與問題清單
- 長輩關懷：定時問候，沒回應時通知子女，加上防詐提醒
- 健康數據（血壓、血糖）彙整成圖表

### 行程與溝通
- 家庭共享行事曆，找出全家都有空的時段
- 家庭群組小秘書：回答行程相關問題
- 重要文件管理：證件、保險、車檢到期提醒，文件掃描歸檔

### 車子與房子
- 汽機車保養、驗車、牌照稅和燃料稅提醒
- 居家維修週期提醒、找師傅、比較報價
- 智慧家居串接

### 節日與出遊
- 生日與節日提醒，記住喜好，推薦禮物、訂餐廳
- 人情往來紀錄（紅白包、送禮）
- 出遊：查景點與評價、規劃路線、訂票、依天氣產生行李清單、旅途分帳、遊記整理
- 週末親子活動推薦

### 進階
- 家庭知識庫：隨時查詢（例如「上次修冷氣找哪家」「阿嬤對什麼藥過敏」）
- 主動式建議：例如颱風預警時建議改期、花費異常時提醒

**優先順序原則**：先做頻率高、又很煩人的事（採買、帳單、接送）。牽涉金錢或安全的動作（付款、訂票、長輩照護）必須有人工確認機制。

## 2. 架構決策：共用框架，拆分 agent

**結論：底層共用同一套 runtime，上層拆成不同 agent（家庭 agent、研究 agent……），由 router 分派。**

### 不採用「一個 agent 掛所有工具」的原因
- 工具太多時，模型容易選錯工具
- 兩者的 system prompt 目標衝突（研究：深入、附引用；家庭：簡短、快速、口語）
- 權限風險：研究 agent 讀取外部網頁，可能遭 prompt injection，不應與付款等權限放在一起
- 難以評估與除錯

### 不採用「兩套完全獨立系統」的原因
底層有大量重疊：模型呼叫、tool-calling 迴圈、重試與錯誤處理、工具註冊（建議統一用 MCP）、記憶基礎設施、驗證、log、成本監控、排程。

### 兩者差異

| | 家庭 agent | 研究 agent |
|---|---|---|
| 生命週期 | 長期常駐、事件驅動 | 一次性任務 |
| 主動性 | 會主動通知 | 被動 |
| 狀態 | 長期記憶很重要 | 任務內短期上下文為主 |
| 動作 | 有副作用（付款、訂票、發訊息） | 大多唯讀 |
| 使用者 | 多人，權限不同 | 通常單一使用者 |
| 速度與成本 | 要快、要便宜，可用小模型 | 可以慢，用強模型、平行 subagent |
| 輸出 | 短回覆、通知 | 長報告，附引用 |

### 架構

```
              ┌─────────────────────┐
  使用者 ───▶ │  Router / 主 agent   │
              └──────────┬──────────┘
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     家庭 agent      研究 agent      其他 agent
          └──────────────┼──────────────┘
                         ▼
        共用 runtime：模型呼叫、工具層(MCP)、
        記憶基礎設施、排程、權限、log
```

### 設計原則
1. **agent 即設定檔**：每個 agent 由 system prompt、工具清單、權限政策、模型選擇、記憶範圍定義。新增 agent 只寫設定，不改框架。
2. **agent-as-tool**：研究 agent 可作為家庭 agent 的工具（例如「比較三家兒童保險」），研究 agent 回傳摘要，家庭 agent 再轉成適合家人的回覆。
3. **權限隔離**：研究 agent 沒有付款或發訊息工具。家庭 agent 執行有副作用的動作前，一律要人確認。
4. **記憶分層**：家庭的長期記憶只開放給家庭 agent，研究 agent 只拿到任務需要的最少資訊。

### 何時才完全拆開
- 由不同團隊維護、發布節奏不同
- 規模或延遲需求差很多
- 有法規或資安要求，必須在實體層面隔離個資

### 起步建議
先用現成框架（Claude Agent SDK、LangGraph、OpenAI Agents SDK 等），定義兩個 agent 加一個簡單的 router，之後有需要再拆。
